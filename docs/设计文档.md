## 1. 项目概述

### 1.1 一句话定位

**把屏幕上任意位置的一整块文字，交给一个你选定的角色，读给你听——边读边跟读高亮，还能跟着你走。**

NekoPal 是「**朗读工具**」与「**桌面陪伴**」的交叉点。它**不是聊天机器人**：不做对话、不做语音识别，只做一件事——**把长文变成有角色的声音**。

### 1.2 要解决的问题

| 编号 | 问题 | 现状 |
| --- | --- | --- |
| P1 | **AI 让长文泛滥**：模型动辄输出数百上千字的解释，逐字读完很累 | 只能硬读，或自己手动摘录 |
| P2 | **讲义/文档想在路上听**：通勤、走路、做家务时有「听」的需求 | 没有把讲义变音频的顺手工具 |
| P3 | 系统朗读无跟读高亮、不能换音色；网页朗读插件进不了本机应用 | 体验割裂，需要逐应用找方案 |
| P4 | 商业 TTS 阅读器没有角色，没有桌宠，缺少「陪伴感」 | 只有声音，没有形象 |
| P5 | VTuber 陪伴应用只会**聊天**，不会**朗读你的长文** | 场景错配 |
| P6 | 中英混排（CS 术语、变量名）常被中文语音读坏 | 多数中文 TTS 不区分语言 |
| P7 | 高质量声音克隆 + Live2D 门槛高（CUDA / 模型 / 授权） | 普通人装不动 |

### 1.3 目标（Goals）

- **G1 整块朗读**：能一次拿到「一整块内容」（一整个长回答、整篇文档、选定内容块）并从头读到尾。
- **G2 跟读窗**：朗读时提供**逐词/逐句高亮 + 自动居中滚动**，支持"从当前可视位置开始读"、跳段、回看。
- **G3 自动续读（Follow）**：内容源新增内容时，**只朗读新增部分**，像播报一样不间断。
- **G4 可插拔 TTS 后端**：至少支持 `say`（离线兜底）、`edge-tts`（音色丰富）、`gpt-sovits`（声音克隆）。
- **G5 零依赖可启动**：未安装任何重型依赖时，`say` 后端即可提供完整链路。
- **G6 可插拔角色层（预留）**：角色 = 形象（Live2D）+ 音色 + 人设，通过统一接口接入；**MVP 不实现，但架构必须预留**。
- **G7 音频导出**：能把整篇内容导出为音频文件（通勤播客）。
- **G8 公开可用**：可作为公开开源项目发布，仓库内**不包含任何受版权保护的语音或形象素材**。
- **G9 只做接口，不做分发**：对第三方音色/角色模型，项目只提供**加载接口与规范**，不内置、不下载、不分发。
- **G10 默认即合法**：开箱可用的音色/角色**全部来自明确可用的来源**（系统音色、Edge-TTS 官方音色、VOICEVOX 等），用户无需任何额外素材即可完整使用。

### 1.4 非目标（Non-Goals）

以下内容**明确不在范围内**，避免范围蔓延：

- N1：**不做对话**。不接受语音输入、不生成内容、不做 Agent。它是「读出已有文本」的工具。
- N2：**不做 ASR / 语音识别**。
- N3：不做「控制源应用滚动条」——跨应用控制滚动不稳定。**跟读高亮只发生在自己的跟读窗内**（唯一例外：文件模式下跟读窗自身即渲染该文件）。
- N4：不做 OCR 全屏取词作为主路径（仅保留为**兜底**接口，Phase 4+）。
- N5：不做移动端、不做浏览器扩展、不做云服务。
- N6：不做模型训练界面；GPT-SoVITS 只作为**推理后端**接入。
- N7：**MVP 不实现 Live2D / 桌宠 / Follow / 导出**（这些是 Phase 2–4）。
- N8：MVP 只实现 macOS 抓取层（但接口须跨平台中立，见 6.2）。
- N9：🔴 **不做音色 / Live2D 模型的下载商店，不做内置分发，不提供第三方模型的下载入口。** 项目只提供**加载接口**（`voices/`、`characters/`），素材由用户自行准备。**这条是硬红线，不因任何理由放宽。**
- N10：不做"一键获取某动漫角色音色"之类的引导功能（含教程、外链、内置清单）。

### 1.5 设计原则

1. **朗读是核心，角色是加分**：即使不用角色、不用桌宠，它也必须是一个好用的朗读器。功能优先级永远服从这条。
2. **离线优先，联网可选**：默认后端必须能离线工作；联网后端明确标注。
3. **零依赖可用**：把"能跑起来"的门槛降到最低，把"音色/角色更好"作为可选升级。
4. **接口先行**：可替换的部分一律通过抽象接口接入，主流程不出现 `if backend == "xxx"` 式分支。
5. **能力协商**：后端与角色主动声明自身能力（词级时间戳？变速？口型？），前端据此显示或禁用控件。
6. **内容寻址缓存**：音频以内容哈希寻址，重复文本零成本复用。
7. **只做接口，不做分发**：仓库零素材；第三方音色/角色模型由用户自备。项目提供的是**能力**，不是**内容**。
8. **默认即合法**：开箱默认音色只用明确可用的来源，且**离线可用优先**。
9. **授权透明**：素材的授权状态（能否商用、能否再分发）在配置与界面中**显式可见**，把判断权交给用户。

## 2. 术语表

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 抓取源 | Capture Source | 文本来源，如"整块内容""opencode 插件""文件监听" |
| **整块抓取** | Block Capture | 一次获取**一整段/一整篇**文本（区别于每次只取一个选区） |
| 朗读任务 | Read Task | 一次「请求朗读一段文本」的完整生命周期 |
| 句（句子） | Sentence | 清洗后按标点切出的最小**渲染**单位 |
| 段（分片） | Segment | 一次 TTS 合成产出的音频单元，通常与「句」一一对应 |
| 词级时间戳 | Word Timing | `(t0, t1, text)` 三元组，音频时间轴上的词/字区间 |
| 跟读窗 | Reader | 前端阅读窗口，负责渲染文本、跟随高亮、控制播放 |
| **自动续读** | Follow | 监听内容源，只朗读新增内容的模式 |
| **进度书签** | Bookmark | 记录"读到哪"的持久化位置，用于续读 |
| 音色包 | Voice Pack | 一个音色定义（参考音频或音色 ID） |
| **角色包** | Character Pack | 角色 = 音色 + 形象 + 人设的组合定义 |
| **角色层** | Avatar | 显示角色形象、驱动口型与表情的独立层（可插拔） |
| 能力 | Capability | 后端/角色支持的功能标志位 |
| 内容寻址 | Content-addressed | 用内容哈希作为音频文件名，同内容同文件 |

## 3. 总体架构

### 3.1 四层模型

> 相比"三层"，这里把**角色层**单列出来。它是**可插拔的装饰层**：角色层挂了，朗读功能照常工作。

```
┌──────────────── 抓取层 capture ────────────────┐
│ CaptureSource（可插拔）                          │
│  · http_in     外部程序 POST 整块文本（opencode 插件等）│
│  · file_watch  本地文件打开 / 监听               │
│  · macos_ax    系统选区（可选，非主路径）         │
│  · screen_ocr  屏幕区域 OCR（兜底，Phase 4+）     │
└───────────────────┬────────────────────────────┘
                    │ ReadRequest
┌───────────────────▼────────────────────────────┐
│ 后端 server（FastAPI，单进程）                   │
│  core/pipeline：清洗链 → 分句 → 任务编排          │
│    ├ TextProcessor[]  清洗规则（可插拔）          │
│    ├ Synthesizer      预合成队列（N+1 提前合成）  │
│    ├ FollowEngine     增量合并（自动续读）        │
│    ├ AudioCache       内容寻址缓存                │
│    └ Exporter         音频导出（通勤播客）        │
│  tts 后端注册表（可插拔）：say | edge | sovits    │
└───────────────────┬────────────────────────────┘
                    │ SSE 事件流 + 音频 HTTP
┌───────────────────▼────────────────────────────┐
│ 跟读窗 web（原生 HTML/CSS/JS，无构建）            │
│  · 文本渲染与分片映射 · 高亮跟随 · 自动滚动        │
│  · 播放控制 · 进度书签 · 从当前位置开始读          │
└───────────────────┬────────────────────────────┘
                    │ 状态同步（播放进度 / 当前词 / 情绪）★ 预留
┌───────────────────▼────────────────────────────┐
│ 角色层 avatar（可插拔，MVP 不实现）               │
│  · Live2D 渲染 · 口型同步 · 表情 · 桌宠窗口        │
└────────────────────────────────────────────────┘
```

**关键约束**：
- 抓取层**不知道**用的是哪个 TTS 后端。
- 跟读窗**不知道**音频是本地合成还是联网合成。
- 后端**不知道**文本从哪个应用来。
- **角色层是可选的观察者**：它订阅播放状态，但它的可用与否**不影响**朗读链路。

### 3.4 客户端外壳形态（重要：决定"这是不是一个应用"）

> 本项目的**后端是纯 API 服务**（18 个端点、0 处服务端模板渲染），因此**界面只是一层可替换的外壳**。
> 这条约束是刻意的：换外壳**后端零改动**。

```
                    ┌── 浏览器标签页（当前形态，开发/调试友好）
后端 /api + SSE ────┼── pywebview 原生窗口（下一步）
                    ├── Electron / PySide6 桌宠窗口（Phase 4）
                    └── opencode 插件（已有，完全不经过界面）
```

| 形态 | 成本 | 能得到 | 拿不到 |
| --- | --- | --- | --- |
| 浏览器（现状） | — | 零依赖、改一行刷新即见效 | ❌ **透明背景 / 全局置顶 / 鼠标穿透**（浏览器无此 API）<br>❌ 需保持标签页、需手动解锁自动播放、无托盘、不能开机自启 |
| **pywebview** ✅ 已实现 | ⭐ 极低 | 原生窗口、Dock 图标、无地址栏、可打包 `.app`<br>**实测：自动播放无需用户手势** | ❌ 透明 / 穿透 |
| Electron | ⭐⭐⭐ | 桌宠三件套 + 托盘 + 开机自启 | 需 Node 生态 |
| PySide6（Qt） | ⭐⭐⭐⭐ | 桌宠三件套 + 纯 Python | Live2D 需 `live2d-py` |

**结论（已实测验证）**：
1. **pywebview 外壳已实现**（`nekopal app`）——把"浏览器标签页"变成"可双击打开的窗口"。
2. **不需要原生音频输出**：实测 pywebview 的 WKWebView **允许无手势自动播放**（日志
   `autoplay-ok {shell: true}`），所以 `web/` 一行没改，浏览器里那套 `<audio>` 直接就能用。
   - ⚠️ 踩坑记录：探针最初用 **0 字节 WAV data URL**，在 WebKit 里 `play()` 的 Promise
     **永不 resolve**，连续误导了三轮排查。换成 0.1 秒真实静音 WAV（`web/silence.wav`）后立刻成功。
3. 桌宠三件套（透明/置顶/穿透）仍留到 Phase 4 用 Electron 或 PySide6。
4. 同类项目均走此路：Open-LLM-VTuber（网页版 + Electron 客户端）、`x380kkm/Live2DPet`（Electron）、
   `f25h-233/live2dpet`（PySide6）、`DoroPet_V3`（PyQt5）、`JPet`（C++ + WebView2）。

#### 3.4.1 「窗口常驻最前」调研结论（**待 Phase 4 实施，勿重复调研**）

macOS 上"窗口保持在最前"**不是一个开关，而是三个独立维度**。缺一个就会出现"某些情况下被盖住"：

| # | 维度 | API | 缺失时的症状 |
| --- | --- | --- | --- |
| ① | **层级** | `NSWindow.setLevel_(.floating/.statusBar)` | 被普通窗口盖住 |
| ② | **空间行为** | `setCollectionBehavior_`：`.canJoinAllSpaces` + `.fullScreenAuxiliary` | **切桌面即消失；别人全屏（看视频 / 开会演示）时被盖住** |
| ③ | **形态** | `setOpaque_(False)`（透明）+ `setIgnoresMouseEvents_(True)`（鼠标穿透） | 只是个不透明方块窗口 |

> 📌 **常见误解的解释**：市面应用（如 QQ 视频）"不能保持最前"通常**不是 macOS 做不到**，
> 而是**只设了 ① 没设 ②** —— 所以平时在最前，别人一全屏就没了。

**pywebview（6.2.1）现状（读源码核实）**：

| 能力 | 支持 | 实现位置 |
| --- | --- | --- |
| 层级 | ✅ | `on_top=True` → `setLevel_(NSStatusWindowLevel)` |
| 透明背景 | ✅ | `transparent=True` → `setOpaque_(False)` + `drawsTransparentBackground` |
| 无边框 | ✅ | `frameless=True` |
| **空间行为** | ❌ **完全没设** | 源码中搜不到 `collectionBehavior` |
| 鼠标穿透 | ✅ **已实现** | 网页报「我身上」的矩形 ✗ + 原生用 `CGEventCreate(None)` 读光标（**免授权**）→ `setIgnoresMouseEvents_(True)` 点穿 |
| 原生句柄（pywebview） | ❌ **实测不可用** | ~~`window.native` 可用~~ → **读它会让进程 SIGTRAP 崩掉**（见下方「已解决」） |

**✅ 已解决（2026-10-13，实测）**：改用**原生 `NSPanel` 外壳**，能浮在全屏之上 ✅

排查过程（留作记录，别重复走）：

## 4. 接口契约

> 本章定义**跨层契约**，是全项目最重要的部分。任何新增能力都应通过扩展本章的接口实现，而不是新增旁路调用。

### 4.1 通用约定

- 基础路径：`http://127.0.0.1:8787`

#### `GET /api/read/{task_id}/events`（SSE）

```
event: plan
data: {"task_id":"tsk_8f31c2","sentences":[{"i":0,"text":"在任意应用里选中一整块文字，"},{"i":1,"text":"按下快捷键。"}],"append":false,"streaming":false}

event: segment
data: {"i":0,"audio":"/api/audio/3ac91f2b","duration":2.41,"words":[{"t0":0.0,"t1":0.18,"text":"在"},{"t0":0.18,"t1":0.42,"text":"任意"}]}

event: segment
data: {"i":1,"audio":"/api/audio/77bd0e19","duration":1.12,"words":[]}

event: done
data: {"task_id":"tsk_8f31c2","elapsed":3.9}

# —— 自动续读（Follow）时，同一 task_id 会再次收到 plan ——
event: plan
data: {"task_id":"tsk_8f31c2","append":true,"sentences":[{"i":7,"text":"这里是新输出的一段前言。"}]}
```

| 事件 | 时机 | 关键字段 | 前端行为 |
| --- | --- | --- | --- |
| `plan` | 分句完成后**立即** | `sentences[]`、`append`、`streaming` | `append=false` 时清空并渲染全文；`true` 时**追加**（不动正在播的内容） |
| `segment` | 每一段合成完成 | `i`、`audio`、`duration`、`words[]` | 入队播放；`words` 为空则退化为句级高亮 |
| `done` | 本轮全部完成 | `elapsed` | 若为 Follow 源则保持订阅，等下一轮 `plan` |
| `error` | 任一步失败 | `code`、`message`、`segment_index?` | 显示错误，跳过该段或终止 |

> `plan` 与 `segment` 分离是刻意设计：**文本先到，声音后到**，用户看到内容立刻出现，即使合成有延迟也不会觉得"卡住"。

#### `POST /api/read/{task_id}/append`

「边写边读」（Follow）的内核：把内容源**到目前为止的全文**并进同一个任务。

```json
{ "text": "（消息到目前为止的全文，不是增量）", "final": false }
```

**关键设计：客户端只发全文，增量由服务端算。**

| 项 | 说明 |
| --- | --- |
| `text` | **全文**（不是增量）。因此客户端可以放心**重发、乱序发、重复发** —— 服务端只认「最长公共前缀」，重复发送是**幂等**的 |
| `final` | 这一轮是否已生成完。`true` 会把剩下的（含没有句末标点的收尾句）一并收进来，并关闭句流 |
| 返回 | `{ "appended": 3, "total": 12, "start_index": 9 }`；前文被改写时返回 `{ "appended": 0, "conflict": true, "conflicts": 1 }` |

**为什么在「句子列表」上做 diff，而不是在「文本」上做：**

`split_sentences` 末尾有一个「过短的句子并进下一句」的合并步骤
（`MIN_SENTENCE_LEN = 8`）—— 结果是**最后一句会随着后续文本继续变长**。
文本级的"最长公共后缀"在这种情况下会误判成"没变化"或"全变了"。

因此实际算法是（见 `core/append.py`）：

1. 把新全文重新**清洗 + 分句**
2. 取 `sentences[:-1]` 作为**已定稿的稳定前缀**（最后一句还可能被改写）
3. 与「上次已提交的句子列表」做**最长公共前缀**比对
4. 前缀对得上 → 多出来的那几句就是新增，推 `plan { append: true }` 并立刻合成
5. 对不上（**前文被改写**）→ **一句都不追加**，只记一次 `conflict`

> 第 5 条是刻意的：**已经念出去的内容收不回来**，
> 宁可不补，也不要把同一句再念一遍（那比"晚半秒"难受得多）。

### 4.3 `options` 开放字段

刻意设计成**开放对象**的扩展点。已定义字段：

| 字段 | 类型 | 默认 | 说明 | 影响音频？ |
| --- | --- | --- | --- | --- |

### 4.7 音色与角色的授权模型

> 本项目**只提供加载接口，不提供任何素材**（G9）。因此"授权状态的表达与透明"本身就是设计的一部分。

#### 授权等级（`license` 字段）

| 等级 | 含义 | 示例 | 界面标记 |
| --- | --- | --- | --- |
| `official` | 随系统 / 公开服务 / 项目自身提供，来源明确可用 | `say` 系统音色、Edge-TTS 官方音色、VOICEVOX 角色 | 正常 |
| `self-recorded` | 用户自己录制的声源 | 用户克隆自己的声音 | 正常 |
| `licensed` | 已获得明确授权 | 委托录音、CC0 数据集 | 正常 |
| `public-domain` | 公有领域 | 部分公开语料 | 正常 |
| `unofficial` | **来源不明 / 未获授权**（第三方分享的角色模型多属此类） | 网盘/群里流通的动漫角色模型 | ⚠️ **黄色警告** |

#### 两个布尔字段

| 字段 | 含义 | 影响 |
| --- | --- | --- |
| `commercial_ok` | 能否用于商业场景（导出后发布、用于商业作品） | 导出时若为 `false` 则提示 |
| `redistributable` | 能否随项目/作品再分发 | 导出/分享时若为 `false` 则提示 |

#### 默认音色策略（Default Voice Policy）

1. 默认音色**必须是 `official` 等级**（合规红线，不因任何理由放宽）。
2. 默认音色可以选**体验更好但需要联网**的 Edge-TTS（当前为 `edge:zh-CN-XiaoxiaoNeural`「晓晓」），
   但**必须同时配置离线兜底音色**（`fallback_voice`，默认 `say:auto`）：
   - **后端不可用**（依赖未装 / 命令不存在）→ `resolve_voice_id` 直接换成兜底音色；
   - **合成失败**（断网、接口变更）→ **逐句**回退到兜底音色，并用**兜底音色自己的缓存键**落盘，
     这样恢复联网后主音色依然生效；回退时通过 `error` 事件（`code=FALLBACK_VOICE`，每任务只发一次）告知前端。
   - **结论：联网音色只能改善体验，绝不能成为唯一出路。**
3. 用户导入的任何 `unofficial` 音色/角色**默认不启用**，需显式切换。
4. 音色列表中**显示授权等级徽标**；`unofficial` 项标注"仅供个人使用，请自行确认合法性"。
5. **项目不提供、不引导、不链接任何第三方模型的下载途径**（见 [1.4](#14-非目标non-goals) N9/N10）。

#### 为什么这么设计

- 与业界通行做法一致：`x380kkm/Live2DPet`——"由于版权原因本库不提供默认模型"；`git2968/Desktop-pet`——"只保留空目录占位，避免把未确认授权的模型一起发布"。
- **工具中性**：能加载任意模型 ≠ 分发侵权物，类似播放器能播放任意视频文件。
- 把合法性判断留在**用户侧且信息透明**，而不是替用户做灰色决定。

## 5. 核心机制

### 5.1 文本清洗管线（TextProcessor Chain）

清洗是为了让"读出来的东西"像人话。规则按顺序执行，每条可独立开关：

| 顺序 | 规则 ID | 作用 | 默认 |
| --- | --- | --- | --- |
| 1 | `normalize` | 统一换行、去零宽字符、全半角归一（保留中文标点） | 开 |
| 2 | `strip_markdown` | 去掉 `**`、`` ` ``、`[]()`、`#`、`|` 等标记语法 | 开 |
| 3 | `skip_code` | 跳过代码块与行内代码（或替换为"（代码）"） | 开 |
| 4 | `skip_tables` | 表格转为简短叙述或跳过 | 开 |
| 5 | `speak_symbols` | `→`、`≥`、`∑` 读成"箭头""大于等于""求和" | 开 |
| 6 | `strip_emoji` | 去 emoji（可选保留为"表情"） | 开 |
| 7 | `limit_length` | 超长截断，保留完整句 | 关 |

> **这条链对「整块朗读 AI 长回答」尤其关键**：模型的回答里代码块、表格、公式很多，不过滤会让朗读很吵。

### 5.2 分句与分片

- **分句**：按 `。！？；\n` 与英文 `.!?;` 切分；过短句（< 8 字）与后一句合并，避免频繁起停。
- **分片**：MVP 阶段**一句 = 一段（segment）**；保留"一拆多"能力（长句按 `，` 再切）以备后端有单次上限。
- 每个分句带稳定索引 `i`，全流程以 `i` 对齐（plan → 合成 → segment → 前端映射）。

### 5.3 高亮同步算法

#### 数据来源

- **词级**：后端返回 `words: [{t0, t1, text}]`（Edge-TTS 的 WordBoundary 提供）。
- **句级**：后端不返回 `words` 时，前端用 `plan` 的句子区间 + 每段 `duration` 生成"整段一个区间"。

#### 关键不变式（重要）

> **时间戳永远相对于「当前正在播放的音频媒体时间轴」。**

推论：
- **若语速通过前端 `audio.playbackRate` 实现**：`audio.currentTime` 本身就是音频时间轴上的位置，会随 `playbackRate` 加快前进 —— **时间戳不需要任何换算**。
- **若语速通过后端合成参数实现**：后端返回的时间戳本就是变速后音频的时间轴 —— **同样不需要换算**。

**所以高亮逻辑与语速实现方式完全解耦。** 这是"预留语速接口"能做得干净的根本原因（见 6.4）。

#### 查找方式

- 每段音频内 `words` 按 `t0` 升序，用**二分查找**定位 `currentTime` 所在区间，复杂度 O(log n)。
- 高亮单元：有词级数据 → 高亮当前词/字块；无 → 高亮当前整句。
- 相邻小块可合并到约 8 字再高亮，减少视觉抖动（纯展示优化，不影响时间准确性）。

#### 落后/超前保护

- 偏差超过阈值（如 0.5s）时以 `t0` 为准重建（应对 seek、暂停恢复）。
- 暂停时高亮冻结。

### 5.4 预合成队列（掩盖延迟）

- 任务创建后立刻启动后台合成协程：先合成第 0 段并推送，随后**播放第 N 段的同时合成第 N+1 段**。
- 并发度默认 2（一个在播、一个在合成），可配置。
- **这是"整篇朗读不卡顿"的关键**：GPT-SoVITS 的 RTF < 1（CPU 上约 0.53），只要预合成 1–2 句做缓冲，往后就永远追得上；用户感知到的"慢"只有**开头那一两秒**。
- 失败重试：单段失败重试 1 次，仍失败则推送 `error` 并跳过该段（不中断整个任务）。

### 5.5 自动续读（FollowEngine）—— 「边写边读」✅ 已实现

用于"AI 一边输出、我一边听"的场景：**不用等整篇生成完**。

**核心抽象**：任务的句子来源从「一个固定列表」换成**可增长、可等待的句子流**
（`core/pipeline.py` 的 `SentenceStream`）。念完已有的会**原地等**新句子，
直到 `final` 到来（或空闲超时）才收尾。

```
内容源（如 opencode 插件）
   │  session.text.delta 按 token 来 → 插件**节流合并**（默认 600ms）
   ▼
POST /api/read/{task_id}/append { text: 全文, final }
   │  ① 重新清洗分句  ② 与已提交的句子列表做最长公共前缀
   ▼
新句子 → SentenceStream.append()
   │
   ▼
任务运行器：emit plan{append:true} → 合成 → emit segment（**无缝续播**）
```

| 项 | 说明 |
| --- | --- |
| 增量判定 | 在**句子列表**上做最长公共前缀（原因见 4.x `append` 契约）—— 不是文本级 diff |
| 冲突处理 | 前文被改写 → **不追加**（只记 `conflicts` 计数，可在 `/api/activity` 看到） |
| 事件顺序 | **先 `plan{append:true}` 再送 `segment`** —— 由任务运行器保证，避免"先有声音后有字" |
| 结束条件 | `final: true`，或空闲超时 `FOLLOW_IDLE_SECONDS = 120s`（防止"其实写完了但没发 final"留下僵尸任务） |
| 与普通朗读的关系 | **同一套代码**：普通朗读 = 一个**创建时就装满并关闭**的流，行为与以前完全一致 |
| 开关 | 请求里 `options.follow = true` **且**服务端 `settings.follow` 为真（环境变量 `NEKOPAL_FOLLOW=0` 可全局关掉） |

### 5.6 进度书签（Bookmark）

- 记录 `{ source_key, sentence_index, audio_offset, updated_at }`，`source_key` 由 `source.session_id` 或文件路径派生。
- 打开同一内容源时提示"上次读到第 N 句，是否继续？"。
- 与 `options.start_index` 配合，实现"从当前位置开始读"。

### 5.7 缓存策略

```
cache_key = sha1(
    text + "\x00" +
    voice_id + "\x00" +
    canonical_json(synth_options)      # 仅包含影响音频的参数
)
```

**必须遵守**：只有**影响音频字节**的参数进入缓存键（`rate`/`pitch`/`volume`/后端专属参数）。
**不得进入缓存键**：`playbackRate`、`start_index`、界面主题、`client_id`。

```
~/.cache/nekopal/audio/<hash16>.wav
~/.cache/nekopal/audio/<hash16>.json   # {text, voice, duration, words, created_at}
```

淘汰：LRU，默认上限 500MB（可配置）。

### 5.8 音频导出（通勤播客）

- WAV：直接把各段 PCM 顺序拼接 → 写出单个 WAV（无需外部依赖）。
- MP3：拼接后用 ffmpeg 转码（缺失时返回 409 并给出安装提示）。
- 段间插入可配置静音（默认 0.15s），避免句子过密。
- 导出过程复用**已有的音频缓存**，不重复合成。

### 5.9 全服事件广播与重复推送去重

「opencode 回答完自动朗读」踩出来的两个坑，都沉淀成了机制。

#### 全服事件流（`GET /api/events`）

外部程序（插件、脚本）推送文本时是**绕开界面**的；跟读窗无从得知。所以：

```
POST /api/read 成功 → runtime.notify("task-created", task_id=…, source=…)
                     ↓
       所有订阅了 /api/events 的跟读窗收到 → 自动接上该任务的 SSE 并播放
```

- 跟读窗用 `currentTaskId` 区分「自己发起的」与「外部推来的」，避免重复接管。
- 事件流带 15s 心跳（`: keep-alive`），防止中间层掐断空闲连接。
- 队列满了**丢帧而不阻塞**主流程。

> 📌 教训：**异步系统里，"数据送对了"不等于"用户能感知"。** 最后一公里往往在**通知层**。

#### 重复推送去重

插件可能被宿主加载成**多个实例**（实测：opencode 会按 location 各加载一次），
同一轮会推送两次 → 表现为"重新从头读一遍"。

- 指纹：`source.session_id + sha1(文本)`
- 在 `dedupe_window`（默认 10s）内命中即返回 `{"deduped": true, task_id: ...}` 且**不创建新任务**。
- 从去重判断到 `tasks.create()` 之间**不允许出现 `await`**，否则并发下会漏判。
- 调试可用 `options.no_dedupe = true` 关闭。

### 5.10 角色窗口与主窗的同步（`/api/ui` · `/api/lip`）

角色窗口是**另一个进程** ✗ —— 它读不到主窗的 localStorage，也拿不到主窗 `<audio>` 的音频。
所以两边只通过**后端**通信（都是小接口 ✗）：

| 接口 | 方向 | 用途 |
| --- | --- | --- |
| `GET/PUT /api/ui` | 主窗 ↔ 角色窗 | `{show_avatar, outfit}`：要不要开人物、选哪个形象 |
| `GET /api/avatar` | 角色窗读 | 形象清单（每个带**动作分组 / 表情 / 有没有物理** ✗）+ `active_outfit` |
| `GET/POST /api/lip` | 主窗写 · 角色窗读 | 音频电平 0..1（**口型同步** ✗；0.4 秒没更新就当静音 ✗） |

- 主窗换形象 → 角色窗**每 3 秒轮询** `/api/ui` → 重挂模型 ✅
- 主窗选「不开人物」→ 角色窗轮询到 `show_avatar:false` → **自己退出** ✅
- 主窗朗读 → WebAudio 算 RMS → POST `/api/lip` → 角色窗 70ms 轮询 → `setMouth()` ✅

> ⚠️ 主窗那侧：`createMediaElementSource` 会把音频**改道** ✗ ——
> 必须再接回 `destination` ✗，否则**直接没声音**。

### 5.11 活动记录（可观测性）

插件的成功路径是**静默**的，出问题只能靠猜。因此引入 `Runtime.activity`（内存环形缓冲，最近 100 条）：

| 端点 | 用途 |
| --- | --- |
| `POST /api/activity` | 上报一次活动（插件、脚本、内部流程） |
| `GET /api/activity` | 查看最近记录 |

插件上报的节点：`module-loaded`（模块被求值）→ `plugin-ready`（setup 跑完）→ `event-type`（事件词表）
→ `trigger` → `no-session-id` / `no-answer` / `pushed` / `deduped` / `push-failed` / `error`。

**一条命令定位卡点**：

```bash
curl -s http://127.0.0.1:8787/api/activity | python3 -m json.tool
```

### 5.12 控制面板（前端即配置界面）

**原则：后端有的能力，界面上就要有入口。** 早期版本里 `Settings` 有 16 个字段，
界面只有 4 个下拉 —— 改一个「边写边读」得去编辑 `~/.config/nekopal/*.json`，
普通用户根本摸不到。

现在主窗底部是一个**标签栏**（`设置 / 导出 / 聊天 / 活动`），只在这一层放"不常碰"的东西；
顶栏只留播放时随时要用的（音色 / 语速 / 形象 / 播放控制）。

| 界面控件 | 落到哪 |
| --- | --- |
| ☑ 自动朗读 opencode 输出 | `settings.auto_read` |
| ☑ 边写边读 | `settings.follow` |
| 自动滚动 / 预取句数 / 缓存上限 | `settings.auto_scroll / prefetch / cache_max_mb` |
| 清空缓存 | `DELETE /api/cache` |
| 开始导出 | `POST /api/export` |

**`auto_read` 的语义**（唯一一个"新造"的开关）：为 `false` 时，
**外部来源**（`source.app != "web"`）的 `/api/read` 直接返回
`{"skipped": true, "reason": "auto_read_off"}` —— **不建任务、不发声**，
但仍在活动记录里留痕；你自己点「朗读」（`source.app == "web"`）不受影响。

**持久化**：这些值写完立刻存进 `~/.config/nekopal/ui.json`（与音色同路），
后端启动时由 `_restore_ui_voice()` 读回 —— 否则"重启就回到默认"，
用户会以为开关坏了。

### 5.13 预生成台词池（`/api/lines`）

**问题**：`/api/avatar/chat` 原本每次点击都打一次大模型 ✗ —— 实测 **+3～4 秒** ✗。
"点一下看她说话"变成"点一下等程序跑"✗，把角色感全毁了 ✗。

**做法**：**一次生成几十句存档**✗，点击时从池子里抽 ✅。

| 端点 | 作用 |
| --- | --- |
| `GET /api/lines` | 池子现状（条数 / 生成时间 / 模型 / 是否过时） |
| `POST /api/lines` | 一次生成一整批（`{count}`，默认 30，上限 80） |
| `PUT /api/lines` | **整份替换** —— 界面上改字 / 删句走这条 |
| `DELETE /api/lines` | 清空 |

**`/api/avatar/chat` 的四级优先**：

```
① line_source=pool 且池子非空  → 抽一句            source: "pool"    （快 ✅）
② 都没抽到 且 配了 LLM         → 现编               source: "ai"      （慢 ✗）
③ 现编失败 但池子非空          → 抽一句             source: "pool-fallback"
④ 什么都没有                   → 角色包静态台词     source: "static"  （"不配也能用"✗）
```

**几个刻意的设计**：

- **抽签袋**（`_BAGS`，仅内存 ✗）：一轮之内**不重复**，抽空自动重填 ✅。
  不落盘 ✗ —— 不值得为它写文件 ✗。
- **池子见底自动补**（`_schedule_refill`）：剩 ≤5 条时**后台线程**悄悄再生成一批 ✗
  （失败静默 ✗）—— 绝不能让你点一下等它 ✗。
- **必须丢线程**：`generate_lines` 是同步阻塞的 HTTP 调用 ✗，
  直接 `await` 会把整个事件循环卡住 ✗（跟读窗也没反应 ✗）→ `asyncio.to_thread` ✅。
- **指纹（`_fingerprint`）**：`sha256(persona + profile)[:12]` 存进 `lines.json` ✗。
  对不上 = 你改过人设或私人信息 ✗ → 界面上提示「⚠️ 建议重新生成」✅
  （**不是错误状态** ✗ —— 旧台词照样能用 ✅）。
- **存放位置**：`~/.config/nekopal/characters/<id>/lines.json` ✗ ——
  它是 `profile.md`（私人信息）的衍生物 ✗，**天然不能进仓库** ✗。

**提示词上的两处针对性修正**（`chat.py`）：

1. **让私人信息真的被用上** ✗：原来的措辞是「不要复述、不要提到"资料"」✗，
   结果模型只敢叫一声称呼 ✗。「关于和你说话的人」那节改成**明确要求**
   挑一件她的近况**用自己的语气点一句** ✅，并给了"宁可小、宁可具体"的示范 ✗。
2. **压住「……」** ✗：人设里写着「经常只回一个词或一个「……」」✗，
   模型就**每句都叹气** ✗ —— 而那个音色（软萌慵懒 ✗）把它念出来就是**一声叹息** ✗。
   批量提示词里直接写死：**整批最多 4 句**用「……」开头 ✗，并禁掉叹词 ✗。

实测（`deepseek-flash`，30 条）：**「……」0 条 · 叹词 0 条 · 涉及用户近况 6 条**，
一次调用 **2.4 秒**。

### 6.1 TTS 后端插件

```python
@dataclass(frozen=True)
class Capabilities:

@dataclass
class SynthResult:

class TTSBackend(Protocol):

```

```python
class CaptureSource(Protocol):
```

### 6.4 播放参数（语速 / 音量 / 音调）★

**两端实现，各司其职**：

| 方式 | 位置 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| A. `playbackRate` | 前端 | 瞬时生效、不重新合成、不联网、免费 | 极端倍率音质下降 | **默认路径**（1.0–2.0 倍） |
| B. 合成参数 `rate` | 后端 | 音质最好 | 需重新合成（走缓存）、有延迟 | 用户显式要求"高质量变速" |

**设计要求**：
1. UI 语速滑条默认控制 A（前端），实时生效，**不触发网络请求**。
2. `options.rate`（B）作为"高质量变速"开关存在，MVP 可只实现 A。
3. **时间戳不需要任何换算**（5.3 的关键不变式）。
4. A 不改变音频字节 → `playbackRate` **绝不进入缓存键**；B 改变音频字节 → `rate` **必须进入缓存键**。

**「小需求」落点表**（以后冒出任何小想法，先来这张表查落点）：

| 需求 | 落点 | 需要改接口？ |
| --- | --- | --- |
| 1.5x / 2x 语速 | 6.4 | 否 |
| 音量 / 音调调节 | `options.volume/pitch` | 否 |
| 段间停顿时长 | `options.add_pauses`（新增键） | 否 |
| 从当前滚动位置开始读 | `options.start_index` + 前端 | 否 |
| A-B 循环复读某一句 | 前端播放器（纯前端） | 否 |
| 逐句暂停（听写模式） | 前端播放器 | 否 |
| 跳过代码块 / 表格 | `options.clean` | 否 |
| 只要选中段落 | 抓取层（`granularity: selection`） | 否 |

#### 6.5.2 Live2D 渲染（2026-10-13 落地）

**结论：用 Live2D 官方 Cubism 5 框架，不用第三方库。**

### 为什么不能用 `pixi-live2d-display`

那个库（0.4.0）是按 **Cubism 4** 的 Core API 写的，而模型是 **moc v5 + Core 5**。
差分**不是补一个字段名能解决的**（逐项比对过）：

| 框架要的 | Core 5 实际 |
| --- | --- |
| `moc.canvasWidth` | undefined —— 挪到了 `model.canvasinfo` |
| `drawables.vertexPositions` | 是「每个部件一个 Float32Array」，库当扁平数组用 |
| `drawables.renderOrders` | 叫 `drawOrders` |

硬跑的后果是**一屏碎片**（每个部件画在自己的局部原点）。**官方框架与 Core 配套**。

### 文件布局（都不进仓库）

```
~/.config/nekopal/core/live2dcubismcore.min.js   Live2D 官方专有运行时（使用者自行获取）
~/.config/nekopal/l2d/pet.js                     我们打包的渲染外壳（内含官方框架）
~/.config/nekopal/l2d/shaders/*.{vert,frag}      框架运行时 fetch 的着色器
```

仓库里只放**我们自己写的东西**：
- `integrations/live2d/nekopalpet.ts` —— 渲染胶水（~330 行）
- `scripts/build_live2d.sh` —— 用 esbuild 打成单个 ES module

> 为什么需要构建：官方框架是 TypeScript，且内部 import **不带扩展名**，
> 浏览器直接加载不了 → 必须过打包器。**这是本项目唯一需要 Node 的环节**，
> 而且只在你**升级框架**时才需要（产物会一直留着）。

### 摸官方 API 踩的坑（改这里之前先看）

| # | 现象 | 真相 |
| --- | --- | --- |
| 1 | 着色器加载不了 | 路径交给 **`renderer.loadShaders(path)`** + `drawModel(path)`，不是 `CubismShaderManager_WebGL.setShaderPath` |
| 2 | 一路 `'gl is null'` | gl 要用 **`renderer.startUp(gl)`** 交进去 |
| 3 | 贴图不显示 | 是 **`renderer.bindTexture(i, tex)`** |
| 4 | 路径变成 `TexturesTextures/` | `getTextureFileName(i)` **已经带目录** |
| 5 | `initialize is not a function` | updater **没有** initialize；眼眨构造是 `(motionUpdated 回调, eyeBlink)` |
| 6 | 呼吸完全不生效（还不报错） | 参数 id 必须是 `CubismFramework.getIdManager().getId(...)` 的产物 |
| 7 | `setScreenRect is not a function` | 在 **`CubismViewMatrix`** 上，不在 `CubismMatrix44` |
| 8 | 拿不到物理 / pose | `_physics` / `_pose` 是 protected → 得**继承** `CubismUserModel` |
| 9 | 动作一播就 `_eyeBlinkParameterIds.length` 抛错 | `CubismMotion` 的该字段**默认 null**，得自己调 **`setEffectIds(eyeIds, lipIds)`** |

### 尺寸（「太扁」的教训）

两个矩阵各管一件事，**别混**：

- **view** 的宽高比必须**等于 canvas 的** —— 否则整个画面被拉伸
- **modelMatrix** 用 `setHeight()` 决定角色占多大

而**角色窗口的宽高比必须接近模型画布**（本模型 1×1.5 = 0.667）：
窗口 400 宽（减掉左侧按钮列 86 / 右边距 10 → 304）× 460 高（减上下 10 → 440）
→ 0.691 ≈ 0.667 ✅。**否则横向放不下，会被裁成"太扁/太细"** ✗

### 三道防线（踩出来的）

1. **帧循环先排下一帧再干活** —— 否则哪一步抛错，动画直接冻住
2. **动作 / 特效各自 try/catch** —— 底线是"画面绝不能因为它们挂掉"
3. **网页 → 原生日志**通道（带调用栈）—— 角色窗口没有开发者工具，全靠它说话

### 眨眼自己实现

框架的 `CubismEyeBlink` 在本模型上内部 id 为 null、一跑就炸 ✗。
但眨眼本质就是「把 `ParamEyeLOpen` / `ParamEyeROpen` 压到 0 再抬回来」，
直接 `model.setParameterValueById()` 更简单可控，也不跟框架较劲。
故 `nekopalpet.ts` 里自己算一个 130ms 的三角波 ✅

### 6.9 变声（音频 → 音频）扩展点 ★

> RVC / DDSP-SVC 这类模型做的是**声音转换**：输入一段人声，输出同内容的另一种音色。
> 它们**不是 TTS，不能直接喂文本** —— 所以必须单独一层。这也是社区动漫角色模型的**主流格式**。

#### 组合管线

```
文本 ──(base_voice 合成)──► WAV ──(变声命令)──► 目标音色 WAV
                 say / edge                     RVC / DDSP-SVC / 任意工具
```

`rvc` 后端实现的就是 `TTSBackend`（文本 → 音频），内部把上面两步串起来 ——
这样**管线、缓存、SSE 一行都不用改**。

#### 不猜任何 API

本项目**不内置模型、也不猜任何变声工具的接口**，只约定「给它一个 WAV，还我一个 WAV」：

```python
class VoiceConverter(Protocol):
    id: str
    def available(self) -> bool: ...
    async def convert(self, request: ConvertRequest) -> Path: ...
```

内置实现只有 `CommandConverter` —— 按模板执行你配置的本地命令：

| 占位符 | 含义 |
| --- | --- |
| `{input}` | 合成出来的原始音频（WAV，24k 单声道 16bit） |
| `{output}` | 变声结果要写到哪里（WAV） |
| `{model}` | 音色包里声明的模型路径 |
| `{index}` | index 文件路径（可为空串） |
| `{pitch}` | 变调半音数（来自 `options.pitch`） |

例：

```bash
export NEKOPAL_RVC_COMMAND='python infer.py {input} {output} --model {model} --index {index} --pitch {pitch}'
```

**这样 RVC、DDSP-SVC、自写包装脚本、docker 命令都能接**，而项目本身不必知道它们的细节。

#### 音色包写法

```yaml
id: my-converted
name: "我的变声音色"
backend: rvc
license: unofficial            # 未获公开授权的模型如实标 unofficial
commercial_ok: false
redistributable: false
rvc:
  base_voice: edge:zh-CN-XiaoxiaoNeural   # 先用谁合成（必填）
  model: voice.pth                         # 必填
  index: voice.index                       # 可选
  command: [...]                           # 可选，覆盖全局命令
```

#### 能力与降级

- `rate` 由 `base_voice` 负责；`pitch` 映射到 `{pitch}`。
- **词级时间戳：透传 base**（2026-10-13 修正）。变声本身**不产生**时间戳，但它**几乎不改动时间轴**
  （实测 5.136s → 5.120s，漂移 **−16 ms / −0.31%**），因此把 `base_voice` 的词级时间戳直接传下去：
  base 是 `edge` 就有词级，base 是 `say` 就自然退回句级。
  `capabilities().word_timings` 仍**保守报 `False`** —— 前端是**看数据**（`segment.words` 非空才逐词高亮），
  不依赖这个标志。
- **输入归一化**：交给变声工具**之前**，base 音频会被统一成 **24k / 单声道 / 16bit**
  （"给 WAV 还 WAV"契约的一部分）。
- **输出采样率不做假设**：从 WAV 头读（RVC 实测输出 **48k**，此前代码写死 24000 是错的）。
- 自检命令：`nekopal convert test --pack my-converted`（合成 → 变声 → 报告，附排查清单）。

## 8. 风险与合规

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | **Edge-TTS 是非官方接口**，可能变更或失效，大量调用可能违反服务条款 | 默认音色路径不可用 | ① 后端可插拔；② 保留**离线** `say` 兜底；③ 隐私说明中明确"文本会发送至微软服务器" |
| R2 | **音色素材版权** | 公开项目投诉 / 下架 | ① 仓库**零素材**；② `voice.yaml` 强制 `license` 字段；③ 文档明确"素材合规由用户自负" |
| R3 | **Live2D 双重授权**：Cubism SDK 有独立授权条款；**模型文件本身另有版权** | 法律风险 | ① `characters/` 只放规范；② `character.yaml` 强制 `license`；③ README 说明需自行确认 Cubism SDK 授权 |
| R4 | macOS 辅助功能权限门槛高 | 首次使用失败 | 首启向导图文引导；未授权时给出明确提示与跳转入口。（注：**主路径 `http_in` 不需要该权限**） |
| R5 | GPT-SoVITS 在 Apple Silicon 上速度慢、可能有内存泄漏 | 体验差 | ① 默认不用它；② 预合成队列 + 缓存；③ 启动时 warmup 一次 |
| R6 | 中文 WordBoundary 切分粒度碎 | 高亮块大小不均 | 按时间戳反查原文位置（5.3），必要时合并相邻小块 |
| R7 | 长文本一次性合成造成内存/延迟问题 | 卡顿 | 强制分句分段；`max_chars` 限制；队列并发度可配置 |
| R8 | **范围蔓延**（"顺便加个 XX"） | 永远做不完 | 严守 1.4 非目标；新需求先查 [6.4 落点表](#64-播放参数语速--音量--音调) |
| R9 | 角色层拖垮 MVP | 交付延期 | 角色层是**可选观察者**；MVP 只放空接口；G6 优先级低于 G1–G5 |
| R10 | **用户携带未授权音色/角色模型**（如同人动漫角色模型） | 项目被卷入侵权争议 | ① 项目**不内置、不下载、不分发**（N9/N10）；② 引入**授权等级**并在界面标记 `unofficial`（4.7）；③ README 与首启向导写明责任在用户；④ 提供合法替代（`say` / Edge-TTS / VOICEVOX / 自录） |
| R11 | **默认音色来源失效**（如 Edge-TTS 接口变更） | 开箱不可用 | ① 默认链首选**离线**的 `say`；② 后端可插拔；③ 提供 VOICEVOX 等本地替代方案 |

### 附录 A：本机实测数据（Phase 0 已填写）

设备：MacBook Air · Apple M5 · 16GB · macOS 26.6 · Python 3.12.15

| 后端 | 测试文本 | 音频时长 | 合成耗时 | RTF | 首段延迟 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| `say`（离线） | 4 句（含中英混排） | 15.19s | 1.95s | **≈ 0.13** | 0.53s | 零依赖、绝对合法 |
| `edge`（联网） | 2 句 | 4.64s | 1.08s | **≈ 0.23** | 0.49s | 提供词级时间戳 |
| `edge` 命中缓存 | 同上 | — | — | — | **0.00s** | 内容寻址缓存生效 |
| `gpt-sovits`（CPU） | — | — | — | 未测 | — | 需 ffmpeg + 模型（Phase 3） |

**结论**：

1. **`say` 比实时快约 8 倍**（RTF 0.13），**首段 0.53s 出声** —— 之前担心的"慢"在本机不成立，"预合成队列 + 缓存"足以把首段压到 0.5s 内。
2. 结合官方 README 的 RTF（M4 CPU 0.526），**即便换成 GPT-SoVITS，连续朗读也不会卡顿**，慢的只是起步。
3. `edge` 的 506 个官方音色全部为 `official` 授权等级，符合 G10「默认即合法」。
