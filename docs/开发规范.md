## 1. 环境与工具链

### 1.1 必备

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.11+ | 后端与 CLI |
| [uv](https://github.com/astral-sh/uv) | 最新 | 依赖与环境管理，**统一使用 uv，不用全局 pip 装包** |
| ffmpeg | 最新 | **仅两处需要**：GPT-SoVITS 后端、导出 mp3（`brew install ffmpeg`） |

### 1.2 开发环境初始化

```bash
cd NekoPal
uv venv                       # 创建 .venv
uv pip install -e ".[dev]"    # 可编辑安装 + 开发依赖
uv run nekopal serve          # 启动本地服务
uv run pytest                 # 跑测试
```

### 1.3 关于 Node

本项目**不使用 Node / 打包构建**。前端为原生 HTML/CSS/JS，由后端直接托管。
如需引入任何需要构建步骤的前端工具（例如 Phase 3 的 Live2D 渲染库），**必须先在设计文档中记录并说明理由**。

### 1.4 可选依赖分组

`pyproject.toml` 中按分组声明，保证"零依赖可跑"：

```toml
[project.optional-dependencies]
edge    = ["edge-tts"]           # 音色丰富，需联网
sovits  = ["requests", "pyyaml"] # 需要外部运行 GPT-SoVITS 服务
macos   = ["pyobjc-framework-ApplicationServices", "pyobjc-framework-Quartz"]
avatar  = ["pyyaml"]             # Phase 3：角色层（前端资源为主）
dev     = ["pytest", "pytest-asyncio", "ruff"]
```

## 2. 目录结构约定

严格遵守[设计文档 3.3 节](设计文档.md#33-目录结构目标形态)的布局。要点：

- **`core/` 不得导入 `server/`**（领域逻辑不依赖 Web 框架）。
- **`tts/`、`capture/`、`avatar/` 三者互相独立**，不得互相引用。
- **`avatar/` 在 Phase 1 只有 `base.py` + `registry.py` 空实现**，不要提前写实现。
- 新的抓取源放入 `capture/`，新的 TTS 后端放入 `tts/`，新的角色层放入 `avatar/`，新的清洗规则放入 `core/textproc/`。
- 前端只放 `web/`，不放生成的构建产物。

## 4. Python 代码规范

### 4.1 基本

- 使用 **type hints**，公共函数必须有签名标注。
- 使用 **`ruff`** 做 lint 与格式化（行宽 100）。
- **异步优先**：所有 I/O（网络、子进程、文件读写）使用 `async def`。
- 不得在导入时执行副作用（如启动服务、读配置）。

### 4.2 分层纪律

```python
# ✅ 正确：core 只依赖标准库与自身
# src/nekopal/core/split.py
def split_sentences(text: str) -> list[str]: ...

# ❌ 错误：core 不得依赖 server
# from nekopal.server.tasks import TaskRegistry
```

### 4.3 错误处理

- 领域错误用自定义异常（`TTSFailed`、`VoiceNotFound`），由 `server` 层统一转成 HTTP 状态码（见设计文档 4.2 错误码）。
- **不得吞异常**：捕获后必须记录日志或重新抛出。

### 4.4 日志

- 使用标准 `logging`，logger 名用模块路径。
- 不记录完整用户文本（隐私）；需要时只记录长度与首 20 字符。

## 5. 前端规范

- **原生 ES modules**，不引入框架、不使用打包器。
- 禁止在 HTML 中写内联事件（`onclick="..."`），统一 `addEventListener`。
- 与后端的交互集中在一个模块（建议 `api.js`），不在渲染代码里散落 `fetch`。
- **能力协商**：任何控件在启用前先查 `capabilities`，不支持就隐藏或禁用（不得假设后端一定支持）。
- 高亮逻辑集中在 `player.js`，与服务端实现解耦（见设计文档 5.3）。
- **角色层必须可选**：角色初始化失败时，只隐藏角色区域，**不得影响朗读**（用 try/catch 包住整块角色初始化）。

## 6. Git 约定

### 6.1 首次初始化（需先确认）

```bash
cd NekoPal
git init -b main
git add -A
git commit -m "chore: initial project scaffolding and design docs"
```

> 仓库尚未创建。**创建本地仓库与远端仓库前需先与项目负责人确认**（包含仓库可见性、LICENSE 选择）。

### 6.2 分支

| 分支 | 用途 |
| --- | --- |
| `main` | 稳定可运行，**任何时刻都必须能跑通 Phase 1 验收清单** |
| `feat/<短描述>` | 新功能 |
| `fix/<短描述>` | 缺陷修复 |
| `docs/<短描述>` | 仅文档改动 |

### 6.3 提交信息（Conventional Commits）

```
<type>(<scope>): <简述>
```

允许的 `type`：`feat` `fix` `docs` `refactor` `test` `chore` `perf`
常用 `scope`：`core` `server` `tts` `capture` `avatar` `web` `packs` `docs`

示例：

```
feat(tts): add edge-tts backend with word boundary timings
feat(web): support 1.5x/2x playback rate
feat(core): implement follow-mode incremental merge
docs(design): clarify timestamp-speed invariant
fix(capture): fall back to clipboard when AX selection is empty
```

### 6.4 提交前

- 提交前必须跑 `uv run pytest` 与 `ruff check`。
- **不得提交**：音色素材、Live2D 模型、模型权重、`.venv/`、缓存目录、任何密钥。

### 6.5 `.gitignore` 必备条目

```
.venv/
__pycache__/
*.pyc
.cache/

# 音色素材
voices/*/ref.wav

```

## 7. 文档约定

- 文档语言：**中文**；代码标识符、接口字段、专有名词保留英文。
- **接口契约以[设计文档第 4 章](设计文档.md#4-接口契约)为唯一事实来源**。改接口必须先改文档。
- 新增"小需求"时，先在设计文档 6.4 的落点表中确认位置，再动代码。
- 重大决策记入设计文档[附录 B](设计文档.md#附录-b命名与仓库决策记录)，不要只留在提交信息里。
- 不使用大段 emoji；术语首次出现时给出中英对照。

## 8. 测试约定

### 8.1 原则

- **测试不得依赖网络**：默认全部离线。
- **测试不得依赖真实 TTS 或真实 Live2D**：使用 `tests/fakes/` 中的假实现。

### 8.2 假实现

```python
# tests/fakes/silent_backend.py
class SilentBackend:
    """返回固定时长的静音音频与固定词级时间戳，用于离线测试。"""
    id = "fake"
    def capabilities(self): ...
    def list_voices(self): ...
    async def synth(self, text, voice, options): ...

# tests/fakes/dummy_avatar.py
class DummyAvatar:
    """只记录收到的 PlaybackState，用于验证角色层协议。"""
```

- 打网络/真实模型的测试用 `@pytest.mark.live` 标记，默认不运行（`-m "not live"`）。

### 8.3 必须覆盖的行为

- [ ] 分句：中英混排、超长句、仅标点、空文本
- [ ] 清洗链：Markdown 去标记、代码块跳过、符号朗读
- [ ] 缓存键：相同内容命中；不同 `rate` 不命中；不同 `playbackRate` **仍命中**
- [ ] 能力协商：无 `word_timings` 时不报错、降级为句级；无角色层时不报错
- [ ] 任务生命周期：创建 → 事件顺序（`plan` 先于 `segment`）→ `done`
- [ ] 中断：`interrupt=true` 时旧任务被取消
- [ ] **Follow**：增量合并只朗读新增部分（前缀重叠、整段重发两种场景）
- [ ] **书签**：同一 `source_key` 能恢复到正确的句子索引
- [ ] **导出**：WAV 无需 ffmpeg；mp3 缺 ffmpeg 时返回 409
- [ ] **授权字段**：缺 `license` / `commercial_ok` / `redistributable` 的包被跳过；`unofficial` 默认不启用；默认音色均为 `official`

## 9. 如何新增一个扩展

### 9.1 新增 TTS 后端

1. 在 `tts/` 新建实现，实现 `TTSBackend` 协议（设计文档 6.1）。
2. 在 `tts/registry.py` 注册。
3. 声明准确的 `Capabilities`（**不要谎报** `word_timings`）。
4. 在 `pyproject.toml` 加一个 optional 依赖分组。
5. 在 `tests/fakes/` 加可离线跑的变体。
6. 更新设计文档 4.2 的 `/api/backends` 示例与本文件 1.4。

### 9.2 新增抓取源

1. 在 `capture/` 新建实现，声明 `platform` 与 **`granularity`**（`block` / `selection`）。
2. 注册并决定是否默认启用。
3. **不得**从抓取层直接调用 TTS 后端；只产生 `ReadRequest`。

### 9.3 新增清洗规则

1. 在 `core/textproc/` 新建实现，给出稳定 `id`。
2. 注册，决定默认是否开启。
3. 补测试用例；更新设计文档 5.1 的表格。

### 9.4 新增播放参数（如语速）

1. 先判断属于**播放侧**还是**合成侧**（设计文档 6.4）。
2. 播放侧 → 只在 `web/player.js` + 设置中实现，**不新增后端字段**。
3. 合成侧 → 加入 `options`（开放对象），并确认是否需要进入缓存键。
4. 无论哪种，**时间戳都不需要换算**（设计文档 5.3 不变式）。

### 9.5 新增角色层 / 角色包（Phase 3）

1. 实现 `AvatarBackend` 协议（设计文档 6.5），并在 `avatar/registry.py` 注册。
2. **角色层不得被朗读链路依赖**：只能通过 `PlaybackState` 观察。
3. 前端资源放在 `web/avatar/`，由 `render_web_assets()` 声明。
4. 角色包规范见设计文档 4.5；**仓库内不得提交任何模型文件**。
5. 补一个 `tests/fakes/dummy_avatar.py` 验证协议，以及"角色层不可用时降级"的用例。
